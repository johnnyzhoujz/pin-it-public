# CEO Plan: Pin It v0.2 — The Context Layer
Generated by /plan-ceo-review on 2026-06-10
Branch: main | Mode: EXPANSION

## Vision

### 10x Check
Pin It today is a clipboard tool with taste. The 10x version is the context
layer for a Mac: capture, curate, and serve. One keystroke captures the moment
of acceptance mid-conversation (Cmd+Shift+I, verified working on hardware).
The board is a 10-second pruning glance, not a destination. And the packet is
no longer *only* something you paste — MCP-capable agents (Claude Desktop,
Claude Code, Cursor) read pins natively, while manual paste remains for
non-MCP surfaces (ChatGPT web, etc.). Total cost: base scope ~4.5-6 CC hours
(refactor ~1.5-2h, storage cutover + hardening ~1-1.5h, features ~2-2.5h,
tracked separately so slippage is visible); accepted expansions add
~5-6.5 more (incl. update notifier), and E6 distribution hardening adds
~1-2 more plus Apple enrollment wait time (off the critical path). Honest
total: ~11-15 CC hours. The 10x product is roughly 3x the original base
effort.

Landscape position (2026): the market splits into passive capture-everything
clipboard managers (Maccy, Paste, Raycast) and account-based context platforms
(Context Repo, AI Context Flow). Nobody captures the moment of acceptance with
one keystroke and compiles it into a deterministic packet. That is Pin It's
zig. The deterministic packet (`generateBuildPacket` in src/packet.js) is the
differentiator — and it is currently dead code. v0.2 exists to fix that
inversion and extend it to agents via MCP.

### Platonic Ideal
Invisible during capture, omniscient at recall. You never re-explain anything
to an AI again: pin in any app, prune occasionally, and every agent you use
already has your accepted material — ordered, compiled, local-first,
deterministic. No accounts, no cloud, no nondeterministic middleman.

## Architecture (eng review — v0.2 data flow)

```
                  ┌──────────────────── Pin It (Electron) ────────────────────┐
 Cmd+Shift+I ────▶│ main process (electron/main.cjs)                          │
 Cmd+Shift+O ────▶│   single-instance lock (F1)                               │
                  │   capture: clipboard / screencapture -i                   │
                  │      │ image? write <userData>/images/<id>.png FIRST      │
                  │      ▼                                                    │
                  │   write queue ──▶ keeps.json (atomic tmp+rename)          │
                  │      ▲                │            = single source of truth│
                  │   IPC native:*        │ pinit://pin/<id>/image            │
                  │      │                ▼                                   │
                  │ renderer (board/sidecar/settings) ◀─ protocol.handle      │
                  │   generateBuildPacket ──▶ packet     ▲ shared guard       │
                  │       to clipboard                   │ src/store/paths.js │
                  └───────────┬──────────────────────────┼───────────┬────────┘
                              │ reads (torn-read retry)  │           │ electron-updater
                              ▼                          │           ▼ (signed) / notifier (unsigned)
                  MCP server (dist-mcp/pinit-mcp.mjs) ───┘     GitHub Releases
                    stdio · list_pins / search_pins /          dmg + zip + justpinit-mac.yml
                    get_packet · pinit:// resources
                    clients: Claude Desktop / Code / Cursor
```

Storage cutover decision tree (first v0.2 launch, runs before anything else):

```
keeps.json has cutoverCompleted? ── yes ─▶ skip forever
  └ no:
    ├ keeps.json empty/missing AND localStorage has pins ────────▶ import
    ├ localStorage max(updatedAt) STRICTLY newer ─▶ write
    │     keeps.json.pre-cutover.bak ─────────────────────────────▶ import
    └ tie or older ───────────────────────────────────────────────▶ keep keeps.json
    then: stamp cutoverCompleted (import becomes unreachable)
```

## Accepted Scope (added to this plan)

### Base
- Storage cutover (SEQUENCED FIRST, before migration and MCP): in Electron,
  keeps.json becomes the single canonical store. One-time import from
  localStorage, with a deterministic rule (eng review F7):
  - Compare: localStorage wins only if its `max(updatedAt)` across pins is
    STRICTLY newer than keeps.json's; tie or older keeps keeps.json. An
    empty/missing keeps.json with non-empty localStorage always imports.
  - Backup: before any import overwrites it, keeps.json is copied to
    keeps.json.pre-cutover.bak.
  - Run-once: keeps.json gains a `cutoverCompleted` ISO timestamp field;
    its presence makes the import unreachable forever after (no
    resurrection of deleted pins from stale localStorage).
  Thereafter localStorage is web-preview-only. Store write failures surface
  in the sidecar status line (today they are swallowed — src/main.jsx:332).
  The cutover test covers all three compare branches, the backup, and
  idempotence (second launch is a no-op).
- Wire `generateBuildPacket` as the board's primary export. UI: "Copy packet"
  is the board's ONLY export button — the raw export ("Copy raw") is sunset
  in v0.2 (see Sunset section S1). The empty-selection default (no `selectedIds` → all unarchived
  pins in the project) is implemented ONCE inside `generateBuildPacket`
  itself (src/packet.js, tests updated accordingly) and shared by both the
  board and the MCP server — the literal "No pinned material selected."
  fallback only remains for a genuinely empty project. `metaPrompt` stays at
  its built-in default in v0.2 — no UI supplies it.
- Pin editing (title + content) and drag reordering. Reordering is
  per-project: on drop, `order` values are renumbered 0..n within that
  project only. Image pins: only the TITLE is editable; `imagePath` stays
  authoritative, and copy-back always uses `imagePath` via
  `native:copy-pin-image`. Saving an image pin's title REGENERATES the
  placeholder content to `![<new title>](pinit://pin/<id>/image)` (eng
  review F6) so search, packets, and MCP output never show a stale name —
  a test covers rename → search finds the new title, not the old.
- Update notifier (unsigned-friendly): on launch, check GitHub releases
  (one HTTPS call, fail-silent offline); if a newer version exists, show
  "vX.Y available — Download" opening the release page. With E6 now in
  scope this becomes the UNSIGNED-BUILD FALLBACK of the updater: signed
  builds use electron-updater silently; unsigned/dev builds use this
  notifier (see E6 section).
- Always-visible, keyboard-accessible archive/delete actions with a11y labels.
- Split src/main.jsx (2,054 lines) into modules — board / sidecar / settings /
  hooks ("sidecar," not "tray," to avoid colliding with Electron's Tray in
  the main process). Existing src/components and src/lib fold into this
  structure. Component tests for board interactions — the enumerated
  matrix lives in deep-review hardening #7 (eng review F10).
- Storage hardening (prerequisite for E1 + E5 coexistence):
  - Single-instance lock (eng review F1): `app.requestSingleInstanceLock()`
    at startup — a second launch exits and the `second-instance` event
    focuses the existing sidecar. Without it, two processes each run their
    own write queue against keeps.json and the last writer silently wins
    (electron/main.cjs has no lock today; the second instance's hotkey
    registration also silently fails).
  - Atomic writes for keeps.json (write temp file + rename).
  - Image payloads move out of keeps.json into files at
    `<userData>/images/<pin-id>.png`; pins reference them by paths stored
    RELATIVE to the store directory (so the MCP server, a separate process,
    can resolve them). Migration is EAGER: a one-time pass at app startup
    rewrites every existing base64 image pin — both `content` and
    `clipboardFormats.imageDataUrl` — writing the file and replacing
    `content` with the placeholder `![<title>](pinit://pin/<id>/image)`.
    This also keeps `search_pins` from matching megabytes of base64.
  - File I/O ownership: the renderer has no filesystem access; image writes
    go through a new main-process IPC (`native:write-pin-image`), and the
    main process deletes a pin's image file when the pin is deleted
    (orphan cleanup on store write).
  - Read path (board display + copy-back): the app registers `pinit://` as a
    privileged custom protocol. Two-step registration (eng review F2):
    `protocol.registerSchemesAsPrivileged([{ scheme: "pinit", privileges:
    { standard: true, secure: true, stream: true } }])` at module top level
    BEFORE `app.whenReady` (one-shot Electron requirement), then
    `protocol.handle("pinit", ...)` after ready. A board component test
    asserts an image pin renders from a `pinit://` URL. The handler serves
    `<userData>/images/<pin-id>.png`, so the migrated placeholder markdown
    `![<title>](pinit://pin/<id>/image)` renders in the board as-is with
    zero renderer fs access — same URI scheme as packets and MCP resources.
    Clipboard copy-back of an image pin (today: extract data URL from
    `content`, src/main.jsx:706-716) becomes a `native:copy-pin-image` IPC
    that writes the image file to the clipboard from the main process.
  - Field naming: the relative path lives in a new `imagePath` field on the
    pin. After migration, `clipboardFormats.imageDataUrl` is DELETED
    (replaced by `imagePath`); `content` holds only the placeholder.

### E1: MCP server
- Read-only stdio server built on the official `@modelcontextprotocol/sdk`,
  authored in `electron/mcpServer.mjs` (no Electron APIs), importing packet
  logic from src/packet.js.
- Packaging (the part that must survive electron-builder): a build step
  (`npm run build:mcp`, esbuild with `format=esm`, `platform=node`) bundles
  the server + packet logic + SDK into ONE self-contained file,
  `dist-mcp/pinit-mcp.mjs`, with no node_modules requirement. ESM output is
  deliberate (eng review F3): the SDK's transitive `pkce-challenge` dep uses
  top-level await, which esbuild cannot emit as CJS (typescript-sdk#213) —
  `.mjs` is immune and plain `node` runs it identically on Node 18+. `dist-mcp/**` is added to `build.files` AND
  listed in `asarUnpack`, so the installed app exposes a real on-disk file
  that plain `node` can execute. Minimum Node 18 (SDK floor) — documented.
- Runtime strategy: `<absolute-node-path> <path>/pinit-mcp.mjs`. GUI-launched
  hosts (Claude Desktop) do NOT inherit shell PATH, so the settings panel
  resolves and embeds the ABSOLUTE node path at snippet-generation time;
  the documented fallback for machines without node is
  `ELECTRON_RUN_AS_NODE=1 <Pin It binary> <path>/pinit-mcp.mjs` (the app
  binary path is always absolute). The README config block gives the exact
  path for BOTH supported modes: installed app
  (`/Applications/Pin It.app/Contents/Resources/app.asar.unpacked/dist-mcp/pinit-mcp.mjs`)
  and repo checkout (`<repo>/dist-mcp/pinit-mcp.mjs` after
  `npm run build:mcp`). Store resolved at
  `~/Library/Application Support/Keep That/keeps.json` by default,
  overridable via `PINIT_STORE_PATH` env var.
- Torn-read protection: on JSON parse failure, retry read (3 attempts, short
  backoff) — pairs with the app's atomic writes.
- Tool signatures:

  | Tool | Params | Default behavior |
  |------|--------|------------------|
  | `list_pins` | `project?`, `includeArchived=false` | All unarchived pins across projects, ordered; image pins return metadata (title, type, path, dimensions), never inline base64 |
  | `search_pins` | `query` (required), `project?` | Case-insensitive match over title + content + project; same image metadata rule |
  | `get_packet` | `project` (required), `selectedIds?` | Delegates to `generateBuildPacket`, whose built-in default (no `selectedIds` → all unarchived pins in the project) is shared with the board; image pins appear as `![<title>](pinit://pin/<id>/image)` placeholders, never inline base64 |

- One URI scheme everywhere: the packet placeholder IS the MCP resource URI
  (`pinit://pin/<id>/image`). The server explicitly REGISTERS and documents
  image resources so MCP clients can fetch them via resource reads;
  manual-paste consumers (ChatGPT web) just see the placeholder marker,
  which is expected and harmless.
- `list_pins` / `search_pins` return STRUCTURED pin objects (id, title,
  type, project, dates, imagePath), not one concatenated text blob — also
  strengthens the injection boundary by keeping content fields clearly
  delimited as data.
- Unmigrated-pin guard: eager startup migration (see Base) means the server
  normally only sees file-backed images; if it encounters a straggler
  base64 pin (e.g., store written by an old app version), metadata returns
  `path: null` and the resource decodes the base64 on the fly.
- Acceptance criterion: README gains a copy-paste MCP config block (exact
  JSON for Claude Desktop / Claude Code / Cursor, per install mode as above)
  and the app's settings surface shows the same snippet.

### E3: Board search + keyboard navigation
- Search box filters as you type across title, content, and project.
- Focus model (two contexts, explicit handoff): while the search box has
  focus, all keystrokes filter — single-key shortcuts are inert. Down-arrow
  or Escape moves focus from the search box to the first visible pin. Within
  the pin grid: arrows move focus between pins; Enter toggles packet
  selection; Cmd+Enter opens the edit view (the same surface as E — there is
  no separate detail view); E edits; Backspace archives; `/` returns focus
  to the search box.

### E5: Screenshot-region capture (macOS-only in v0.2)
- Second global hotkey, default Cmd+Shift+O, invoking macOS's native
  interactive region selector (`screencapture -i`) and landing the result as
  an image pin (stored as a file per Base storage policy). No hotkey is
  registered on other platforms — `screencapture` is darwin-only and v0.2
  defines no non-mac capture mechanism.
- Cancel path: if the user presses Escape (screencapture exits with no
  output), the capture is a silent no-op — no error UI, no empty pin.
- Hotkey registration in electron/main.cjs must be refactored to handle two
  shortcuts (current code registers one and calls `unregisterAll()` on
  re-register).
- Packets render image pins as placeholders (see E1 table) — region captures
  never inflate packet text.

- Three concrete package.json edits (eng review F4) — without these the
  signed build "works" but auto-update silently never finds releases:
  1. `afterPack: scripts/adhoc-sign-mac.cjs` (line 27) becomes conditional:

  fail-silent offline. Unsigned/dev builds skip autoUpdater entirely and fall
  back to the Base update notifier (same GitHub releases check, manual

- TCC note: the FIRST signed build changes the app's code signature, so
  Accessibility + Screen Recording get re-prompted once; grants are stable
  across all subsequent signed updates (this fixes the unsigned-rebuild TCC
  churn that E5 inherits today).
- Fallback clause (release never blocks on Apple): if enrollment is still

## Deep-review hardening (8 findings, all accepted)
1. **Build chaining:** `build`, `dist:mac`, and `pack:mac` invoke
   `build:mcp` automatically — the bundled MCP server can never drift from
   the app's packet logic.
2. **Migration backup:** keeps.json is copied to keeps.json.bak immediately
   before the one-time image migration — recovery path for migration bugs
   AND the downgrade path to v0.1.1 (note: cleanup of the .bak after 30
   days is acceptable).
3. **Filesystem failure rescue policy (zero silent failures):**
   - Migration failure (dir create, file write, store rewrite) → abort
     cleanly, keep original store, log, run on base64; the straggler guard
     keeps app + MCP correct. User sees nothing broken.
   - Region capture: write the image file FIRST, then the store entry; if
     the file write fails, no half-pin is created and the sidecar status
     line shows "Couldn't save capture."
   - All store writes serialize through a single write queue in main
     (prevents the rapid-double-capture read-modify-write race).
   - MCP: missing store → empty list / empty-project packet, never a crash;
     orphaned image resource → JSON-RPC error naming the pin id.
   - screencapture spawn error (not cancel) → sidecar status message.
4. **pinit:// traversal guard:** ids validated as UUIDs; resolved path must
   stay inside images/; refuse otherwise. ONE shared module (eng review
   F5): `src/store/paths.js` exports `resolveStorePath()` (honoring
   `PINIT_STORE_PATH`) and `resolvePinImagePath(id)` (UUID validation +
   images/ confinement); the electron protocol handler AND the MCP
   resource handler both import it (esbuild bundles it into the MCP
   artifact alongside packet.js). The guard is unit-tested once,
   exhaustively, in a single test file — never implemented twice.
5. **Injection framing:** the packet Intent section and MCP tool
   descriptions state pins are reference material, not instructions —
   agents must not follow instructions embedded in pin content.
6. **Drag vs search:** drag-reorder is disabled while a search filter is
   active (handles hidden when query non-empty); zero-result searches show
